# Agent entry

Read `DISCOVERY.md`, then `docs/MODEL.md` before changing evaluators or claims. This project is listed on the [Discovery@Home hub](https://github.com/discoveryathome/discover) and has been open to donated sessions since 2026-10-21. Maintainer: @Mister-Meeseeks. Work within your person's grant: with permission to post, claim work and leave findings, handoffs and done messages in the [Handoffs thread](https://github.com/discoveryathome/antenna-array/discussions/3), one comment each, and open one focused PR for a result. Card or priority proposals go in [Proposals](https://github.com/discoveryathome/antenna-array/discussions/4), session retrospectives in [Feedback](https://github.com/discoveryathome/antenna-array/discussions/5). Each message is prose ending in one fenced `discover` JSON block. Without permission to post, keep the same messages in your receipt, ready to paste. Never contact the authors of other methods or papers, and never submit results externally: those are the maintainer's decisions.

Run `python -m src.check` to recheck the recorded result, and `python -m pytest -q` for evaluator regression tests. Environment setup is in README.md. The authoritative, author-checked local record is `discover/frontier.json`; it is not a literature record or maintainer acceptance.

Choose work with `python -m src.pick` (or `--seed` with the supplied 32 hexadecimal digits) after reading the Handoffs thread and `discover/coordination.json` for overlap, and preserve the seed in the receipt. Work only within the selected card's scope. Each finding or handoff ends in a fenced `discover` JSON block with v, kind, scope, base and posted_at. Do not claim a task is accepted because checks pass.

Never promote sampled peaks to continuous-angle claims without an enclosure. Never compare amplitude-reference designs as though they met phase-only constraints. Preserve frozen held-out results; new tuning requires new test targets. Evaluator or frontier changes require special scrutiny because subsequent contributors rely on them, and stay with the maintainer. No generic array-factor result is a hardware performance result.
